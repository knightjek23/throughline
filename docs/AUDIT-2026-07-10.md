# Throughline audit — July 10, 2026

Full pass over the app: security, correctness, and performance. Seven fixes applied directly; the rest are flagged below with recommendations. Overall the codebase is in good shape: RLS policies are correct and consistent, every API route checks auth, model output is Zod-validated and substring-grounded before persisting, secrets are gitignored, and webhook/job routes verify signatures.

## Fixed in this pass

### 1. QStash dev bypass was gated on a public env var (security, high)

`lib/qstash.ts` accepted the `x-throughline-dev-bypass` header whenever `NEXT_PUBLIC_APP_ENV === 'development'`. `NEXT_PUBLIC_*` vars are client-exposed configuration, and preview deploys often set APP_ENV to development. In that state, anyone who found `/api/jobs/analyze-interview` (it's in the proxy's public allowlist) could invoke it with one header: burning Anthropic budget, flipping interview rows to failed, or writing analyses through the service-role client. Now gated on `NODE_ENV === 'development'`, which is only true under `next dev`. Note: if you relied on the direct-fetch fallback in preview deploys, previews now need real QStash env vars.

### 2. Job route trusted the payload for ownership (security, medium)

`analyze-interview` wrote `user_id` into `interview_analyses` straight from the QStash payload. Signed payloads make this low-risk, but combined with issue 1 it was a working privilege path. The route now derives the owner and study from the interview row itself and only logs a mismatch.

### 3. Synthesize route had no rate limit (security/cost, high)

`POST /api/studies/[studyId]/synthesize` is the most expensive call in the app (30 to 60s Anthropic run) and had no cap: a user could fire unbounded concurrent syntheses. Added a `synthesize` limiter (10/hour per user) in `lib/ratelimit.ts` and wired it into the route.

### 4. Public health check let strangers spend your Anthropic budget (security/cost, medium)

`/api/health` is public and pings Anthropic on every hit. A dumb loop against it would run up the bill. Added an IP-based rate limit (20/min). Uptime monitors ping about once a minute, so they're unaffected.

### 5. PostHog server events silently dropped after the first one (bug, medium)

`lib/posthog.ts` called `ph.shutdown()` after each capture but kept the client cached. `shutdown()` permanently disables the client, so on a warm serverless instance every event after the first was dropped. Switched to `flush()`. Also changed `void track(...)` to `await track(...)` in the job and synthesize routes: fire-and-forget promises can be killed when the function freezes after responding.

### 6. Leftover Sentry wizard demo routes (cleanup)

Deleted `app/api/sentry-example-api/` and `app/sentry-example-page/`: dead demo code reachable in production, one of which exists purely to throw errors.

### 7. Dead ternary in upload route (cleanup)

`file.name.endsWith('.txt') ? 'txt' : 'txt'` always returned 'txt'. Replaced with a constant and a note to derive the extension from the validated MIME type when vtt/srt/docx land, not from the user-supplied filename.

## Flagged, not fixed (needs your call)

### A. PWs.txt — plaintext passwords and a live API key (critical)

The project folder root contains `PWs.txt` with Supabase passwords, an email account password, and a live Anthropic API key, all syncing to OneDrive in plaintext. It isn't in git, but it's one account compromise away from all of it leaking. Recommended: move everything to a password manager (1Password, Bitwarden), delete the file, and rotate the Anthropic key and any password in it, since they've now lived in a synced plaintext file.

### B. Plan limits are never enforced (business logic)

`lib/plans.ts` defines trial/solo/pro limits, but no route reads them. Nothing stops a trial user from creating unlimited studies or uploading unlimited interviews; `trial_ends_at` is set but never checked; `usage_counters` is never written. Fine while dogfooding, must land before charging money. Enforcement points: study count check in `POST /api/studies`, per-study interview count + trial expiry in the upload route, `canSynthesize` in the synthesize route.

### C. Delete-then-insert without a transaction in synthesize (data loss, low)

The route deletes existing `study_themes` then inserts the new batch. If the insert fails midway, the user's previous themes are gone. Supabase JS has no transactions; wrap both statements in a Postgres function called via `.rpc()` when you touch this next.

### D. Raw error messages surface to users (info disclosure, low)

`failureReason()` passes unknown error messages (e.g., Supabase internals) into `failure_reason`, which renders in the UI. Truncation to 200 chars limits it, but consider mapping unknown errors to a generic "Something went wrong during analysis" and keeping details in logs only.

### E. Sentry privacy settings (privacy)

`sendDefaultPii: true` plus session replay on an app whose core content is research transcripts. Replay masks text by default, but PII mode sends IPs/headers to Sentry. Worth revisiting before real customer data flows: set `sendDefaultPii: false` and drop `tracesSampleRate` from 1 to ~0.1 in production while you're in there.

### F. RLS defense-in-depth (hardening, optional)

The `interviews` and `study_themes` insert policies check `user_id = clerk_user_id()` but not that the referenced `study_id` belongs to that user. Routes verify ownership first, so there's no live hole; this just makes the DB self-defending. Optional migration:

```sql
-- 0002_rls_hardening.sql
drop policy if exists "interviews_owner_all" on public.interviews;
create policy "interviews_owner_select" on public.interviews
  for select using (user_id = public.clerk_user_id());
create policy "interviews_owner_insert" on public.interviews
  for insert with check (
    user_id = public.clerk_user_id()
    and exists (
      select 1 from public.studies s
      where s.id = study_id and s.user_id = public.clerk_user_id()
    )
  );
create policy "interviews_owner_update" on public.interviews
  for update using (user_id = public.clerk_user_id())
  with check (user_id = public.clerk_user_id());
create policy "interviews_owner_delete" on public.interviews
  for delete using (user_id = public.clerk_user_id());
-- repeat the same split for public.study_themes
```

Run `npm run test:rls` after applying.

### G. Stale duplicates at the folder root (cleanup)

`Dovetail Lite/` root contains an older copy of `app/`, `lib/`, `middleware.ts`, Sentry configs, and a second `.env.local` with real secrets, plus the unused `clerk-nextjs/` starter. None of it runs, but the duplicate `.env.local` doubles your secret surface. Recommend archiving or deleting once you confirm nothing references them.

### H. Smaller notes

- `withRetry()` retries immediately with no backoff; a 250 to 500ms jittered delay would ride out brief 5xx blips better.
- Upload route consumes rate-limit quota before validating the file; harmless, but validating first is friendlier.
- `interview_analyses.model` defaults to a hardcoded model string; write the actual `MODEL` used at insert time so historical rows stay accurate when you bump models.
- `relativeTime()` renders negative values ("-3s ago") under clock skew; clamp to 0.
